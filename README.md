# AURALIS Music

A React/TypeScript and ASP.NET Core music application with a dark glass interface, persistent personal libraries, a global playback queue, Polish/English UI, and replaceable music providers.

**Delivery status:** see [verification report](docs/VERIFICATION.md) for the actual executed checks and remaining gaps. Source code and a CI definition are not proof of passing tests or successful deployment. This is a portfolio application requiring further production hardening, not a licensed commercial music catalog.

## Music sources

- The credential-free selection contains six real Kevin MacLeod tracks streamed from Incompetech, with Creative Commons attribution. Internet access is still required for these audio URLs. See [music credits](THIRD_PARTY_NOTICES.md).
- Set `YOUTUBE_API_KEY` to enable official YouTube Data API metadata discovery. YouTube playback uses the visible official iframe, preserving provider restrictions and advertisements.
- YouTube channels and playlists are not guaranteed to represent musical artists and albums. Complete YouTube Music discographies, unauthorized extraction, ad bypass, and guaranteed gapless audio are not provided.
- The selection is curated, not a measured popularity chart. The collection title is an Auralis editorial grouping, not a claimed commercial album.
- [Provider investigation](docs/PROVIDER_RESEARCH.md) explains the six reviewed open-source implementations and the chosen boundary.

## Windows installation

Install **Git**, **Node.js 22 LTS**, **.NET 8 SDK** (not just the runtime), and **Docker Desktop** with the Linux container engine running. PowerShell 5.1 or newer is supported by the helper scripts. You do not need a GitHub account to run locally.

1. Extract `auralis-music-complete.zip`. Open PowerShell inside the extracted `auralis-music` folder (the folder containing this README).
2. Generate local configuration and start PostgreSQL:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\init-env.ps1
   docker compose up -d --wait
   ```

   The script generates unique database and JWT secrets in `.env`, preserving an existing file. Never commit `.env`. Add your optional YouTube key to that file using a text editor. Docker's volume persists database contents across restarts.

3. Start the backend in this PowerShell window:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
   ```

   The helper imports `.env`, constructs the Npgsql database connection string when `DATABASE_URL` is blank, and runs `dotnet run --project backend/Auralis.Api`. Schema migrations run at startup. API: `http://localhost:5080`; OpenAPI UI: `http://localhost:5080/swagger`; liveness endpoint: `http://localhost:5080/health`.

4. Open a second PowerShell window in the same project root:

   ```powershell
   cd frontend
   npm ci
   npm run dev
   ```

5. Open **http://localhost:5173**. Start in guest mode or register an account. The Vite development server proxies `/api` requests to port 5080.

Guest libraries are stored in this browser's local storage. Registered accounts use PostgreSQL. Guest data is not automatically merged into a registered account; clearing browser storage removes guest data. Registration does not send verification email.

### Configuration details

| Variable | Purpose |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Docker database configuration; local script uses the same values |
| `DATABASE_URL` | Optional full Npgsql connection string: `Host=localhost;Port=5432;Database=auralis;Username=auralis;Password=...` |
| `JWT_KEY` | Random secret of at least 32 characters; generated by initialization script |
| `ASPNETCORE_URLS` | Backend binding; default local helper configuration is port 5080 |
| `FRONTEND_ORIGINS` | Comma-separated allowed browser origins |
| `YOUTUBE_API_KEY` | Optional server-only key for YouTube metadata |

ASP.NET does **not** load `.env` by itself; use the helper or export the variables manually. `DATABASE_URL` is a connection string, not a `postgres://` URI. Only nonsecret frontend configuration belongs in `frontend/.env.local`; `VITE_API_URL` can point to a different API base ending in `/api`. Vite variables are public in the built JavaScript.

If port 5432 is occupied, change the Compose host port and set `DATABASE_URL` to match. Changing `POSTGRES_PASSWORD` after the database volume exists does not change the existing PostgreSQL user's password; update that password deliberately. `docker compose down` preserves data. **`docker compose down -v` permanently deletes the local database.**

## Tests and build

Run from the repository root:

```powershell
dotnet build backend/Auralis.Api
dotnet test backend/Auralis.Tests
cd frontend
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:e2e
```

The production frontend output is `frontend/dist`. It needs a web server with SPA fallback and an `/api` reverse proxy (or an appropriate `VITE_API_URL` at build time). The development Vite proxy is not bundled into `dist`. A production rollout also requires HTTPS, backup/restore testing, secure secret provisioning, monitoring, abuse controls, and a review of browser token storage. The API's liveness endpoint does not verify database or music-provider availability.

## Git history and publication

New commits use actual creation timestamps. No historical dates were assigned. There was no existing Git history at continuation; accumulated work was committed as meaningful source checkpoints. See `DEVELOPMENT_LOG.md` for execution details. `auralis-history.bundle`, when included with the ZIP, preserves the local Git history without packaging an entire `.git` directory.

The complete source is published privately at **https://github.com/energusss/auralis**. Clone it while authenticated as an authorized GitHub user:

```powershell
git clone https://github.com/energusss/auralis.git
cd auralis
```

The original 13 source commits retain their exact IDs and timestamps. Later CI, repair and publication commits use actual creation timestamps. The temporary import setup is archived on `publication/bootstrap`; the application source is on `main`.

The ZIP includes `auralis-history.bundle` as a portable backup of the published history. `scripts/publish-github.ps1` is an optional helper for creating a separate private repository from that bundle with authenticated GitHub CLI. It refuses to overwrite an existing origin or repository; normal use of the published project does not require that helper.

## Project map

- `frontend/`: React, TypeScript, Vite, Tailwind, Motion, Zustand, TanStack Query, React Router and dnd-kit.
- `backend/Auralis.Domain`: entities and normalized music records.
- `backend/Auralis.Application`: provider contracts and security helpers.
- `backend/Auralis.Infrastructure`: EF Core PostgreSQL persistence and music providers.
- `backend/Auralis.Api`: authentication and HTTP endpoints.
- `backend/Auralis.Tests`: backend tests.
- `docs/`: research and verification; [API contract](backend/API_CONTRACT.md).
